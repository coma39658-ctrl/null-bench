# E-ZERO Cloudflare automatic browser calling pilot (NOT DEPLOYED)

Status: 2026-11-05. This branch contains an experimental signaling server and opt-in browser client, but no verified Cloudflare deployment. Public auto-calling remains OFF.

## Research-backed design

WebRTC requires a separate app-defined signaling channel. The existing E-ZERO browser code signs and verifies the exchanged SDP/fingerprints. The separate Cloudflare Worker/Durable Object forwards this SDP without retaining the payload. The room uses a cryptographically random ID, independently random host and guest secrets, and an expiry of 10 minutes.

The Durable Object persists only the SHA-256 room-secret proofs and room expiry temporarily, to stop a guest invitation holder hijacking the host role. It does not store call audio, video, chat or SDP. WebSocket Origin is restricted to the exact GitHub Pages origin.

Cloudflare recommends hibernatable WebSockets and SQLite-backed Durable Objects. Durable Objects are available on Free, subject to usage limits; TURN is a separate service and not configured in this pilot.

## Deployment release gate — do not skip

1. Confirm the right Cloudflare account, least-privilege Workers/Durable Objects deployment permissions and a trusted deployment token. Do not reuse the existing AI/vision worker as the signaling backend.
First deployment needs permission to CREATE a new Worker (Cloudflare currently documents Workers product Admin for initial creation). Afterwards, restrict the deployment token to Editor on the single created Worker where supported. Durable Objects use the implementing Worker's roles. Use two repository Actions secrets, EZERO_SIGNALING_CF_API_TOKEN and EZERO_SIGNALING_CF_ACCOUNT_ID. Never paste either secret into chat; the GitHub Actions manual staging workflow reads them directly.

2. Deploy the isolated staging Worker using Wrangler and its configuration file at signaling/cloudflare/wrangler.jsonc. Confirm the actual Worker URL and functioning WebSocket handshake. GitHub test success alone is NOT a live deployment.
3. Pin the exact worker WebSocket origin in js/ezero_auto_signaling_config_v0_1.js. Keep enabled:false until the next gates pass.
4. Update the Communications HTML Content-Security-Policy connect-src for that EXACT verified WSS origin. Do not allow wildcard hosts. The default CSP currently blocks any external signaling WebSocket.
5. Test two real Android phones on Wi-Fi, then Wi-Fi vs cellular, then Chrome vs Safari/iPhone. Track at least ten test attempts including connected state and two-way audio quality, and record failed setup reasons.
6. Explicit user agreement is needed before the camera/microphone or optional STUN access. Do not claim a signed short-lived key is real-person identity.
7. If different mobile networks fail behind NAT/CGNAT, provision TURN relay with short-lived credentials generated by a trusted backend. Never place TURN API secrets in JavaScript, GitHub Pages or invite links.
8. Test links opened via IMO/WhatsApp: in-app browsers may drop fragments or background/suspend the original call page. Verify before announcing consumer reliability.
9. Test accept/decline, host impersonation prevention, replay and timeouts, mismatched identities, hangup, and browser background behavior. Incoming-call push notifications, offline calling, universal connectivity and persistent chat are NOT implemented.
10. Only after live end-to-end testing, activate the feature flag and present verified calling to the public.
