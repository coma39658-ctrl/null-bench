# E-ZERO Secure Connect — one-link calling threat model & restricted release gate
Date: 2026-11-04 · Owner: E-ZERO · Status: **STAGING DISABLED / NO PUBLIC CALL SERVICE**

## Scope and evidence classification
This work replaces a fragile, multi-kilobyte WhatsApp SDP copy/paste exercise with a short, explicitly shared invitation link and an opt-in one-to-one WebRTC call. It is an **experimental candidate**. The room Worker has been separately deployed to Cloudflare only with `ROOMS_ENABLED=false`; the latest candidate hardening is still under CI and is not the live version until a separate guarded deployment. Synthetic two-mobile Chromium connected-state tests prove a software path, **not** real-Android or independent security validation.

## Research and technology choices
- WebRTC: native browser DTLS-SRTP/SCTP data-channel encryption; secure HTTPS context and deliberate getUserMedia consent. Ref: https://www.rfc-editor.org/rfc/rfc8827.html
- Cloudflare Durable Objects WebSocket Hibernation: event-driven signaling without background polling or idle duration cost. Ref: https://developers.cloudflare.com/durable-objects/best-practices/websockets/
- OWASP WebSocket Security: exact Origin allowlist, distinct auth, per-action role checks, input bounds, rate-limit and no sensitive logs. Ref: https://cheatsheetseries.owasp.org/cheatsheets/WebSocket_Security_Cheat_Sheet.html
- Cloudflare Workers Rate Limiting API: 20 handshake attempts per minute per apparent client IP/location, **approximate**, not a globally strict budget. Ref: https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/

## Applied protections and their limits
| Threat | Control | Residual risk |
| --- | --- | --- |
| Fake signaling room | Only owner-held **random 256-bit hex** `PILOT_OWNER_SECRET` can sign a room's id + one-way authorization token + issued timestamp (HMAC SHA-256). Signatures verified before DO allocation. No operator secret in URL, code or repo. | The person creating a room must trust the E-ZERO HTTPS page and keep the private code safe; compromised device/source can steal inputs. |
| SDP / ICE / IP leakage to signaling operator | Signaling message is already independently ECDSA-signed by the WebRTC client, then encrypted in-browser using an **AES-GCM 256-bit key** in the private invite URL fragment. The Cloudflare WebSocket handshake carries only a **domain-separated one-way SHA-256 derived authorization token**, never that AES key. SDP/ICE not stored or emitted to logs by app code. | The *shared invite URL contains the AES key by design*: a party or intermediary obtaining the entire private link may be able to decrypt observed ciphertext if it can also access that ciphertext. Messaging platforms, compromised devices, screenshots and external recordings are outside this guarantee. |
| Replay / stolen old link | Signed exact timestamp in HMAC, 10-minute lifetime, 128-bit random room ID, one guest slot, one offer + one answer per room, tombstone after decline/hangup, alarm closes sockets, deletes room metadata; old links expire cryptographically even after storage purge. | Someone with a **current unexpired** private link might seize the guest slot before the intended friend. Verify friend's signed fingerprint/person independently. |
| WebSocket takeover / CSWSH | HTTPS/WSS only; exact known Origin; strict WebSocket Upgrade; distinct hashed auth and HMAC proof; role and message-type validation on every action. | The Origin header alone is not authentication for non-browser clients. |
| Flooding or quota depletion | Cloudflare per-network approximate limiter binding, 2 sockets/room, 12 total inbound frames/socket including malformed frames, 180 kB frame cap and 170 kB ciphertext cap, no background polling, staging disabled until release. | The worker now enforces a **strict global eight-room reservation cap** through a singleton SQLite Durable Object, with expiring room IDs and no personal identifiers. Distributed requests may still exhaust Workers Free daily request quota before reaching this gate; confirm account limits, monitoring and fail-closed behavior before enrollment. |
| Permission abuse / fake call success | Separate recipient Accept/Decline; caller Start required; mic/camera only on intentional call; connection shown as successful only when browser WebRTC state is `connected`. On signaling socket/peer failure, stop local media. | Browser/OS malware and third-party screen/audio recording cannot be fully blocked. |
| Persistent data | Room SQLite stores only hashed room authorization and expiration/closed flags for at most 10 minutes; `deleteAll` and `deleteAlarm` on expiry. No server-saved audio/video, chat content or SDP. | Cloudflare may retain operational access metadata under its own practices; the application cannot certify deletion from every provider log/back-up. |
| Client-side injection | Strict same-origin JavaScript CSP and textContent-based visible UI; no remote arbitrary scripts. | Audit third-party dependencies, browser extensions and future changes separately. |

## Required prelaunch gates (do not bypass)
1. Verify the Cloudflare account Free/Paid billing state and confirm limits/alerts and denied write actions; no automatic paid upgrades.
2. Put a **unique random 64-hex owner code** only into the private Cloudflare Worker Secret `PILOT_OWNER_SECRET` via an authorized secret workflow. Do not place the secret in chat, git, screenshots or browser URLs. If possible generate on the operator device and install via a secure Cloudflare setting.
3. Test new hardened code with both fake-WebSocket/browser CI and an actual Cloudflare staging WebSocket endpoint while `ROOMS_ENABLED` remains off by default; limited enablement only under explicit operator control after audit.
4. Complete real two-physical-phone Android tests: same Wi-Fi and separate mobile carriers, incoming/declined calls, wrong/fake HMAC, outdated/forwarded links, background interruptions, audio permissions denied, explicit hang-up, packet loss, IP/STUN consent and network changes. Measure actual `connected` state and both-way audio.
5. Obtain an independent review of WebSocket auth and capability links, browser crypto key handling, privacy disclosure, and 10-minute deletion semantics. The new globally serialized eight-room limit is covered by synthetic tests but still needs live Cloudflare validation; 20/min per-IP rate limiting alone is NOT a global budget.
6. Only then consider restricted 5–10 trusted friends on a reviewed production branch and clear in-app *PILOT* label. Public consumer launch, TURN/SFU, push notifications, group calls, permanent identities and message archives are **not delivered** by this lab.

**No technology can honestly guarantee that fraud, hacking, theft or data leakage is impossible.** The app has no hard prohibition of screenshots or third-party recording. Do not market it as a Signal-equivalent audited messenger or as a verified global phone calling service.
